# Gemini CLI 3.0.0 — keep the conversation close to your project

[Русский](v3.0.0.md) · [English](v3.0.0.en.md)

This release lets a conversation turn into practical work: find a function,
talk through a change, check it and prepare a commit. If an approach does not
work out, restore the file or try another branch of the conversation.

You can also choose two pages or a few cells instead of sending an entire document.
Approvals for reading, writing and running commands stay in your hands.

**Try it:** open a project with `/cd`, ask a small question about the code, then
explore `/dev help` or attach a document using an example from `/doc help`.
The client interface and built-in guides are currently in Russian.

## Return to a long conversation

- Persistent history now has stable turn boundaries, preserving the order of
  messages and tool results through cancellation and recovery.
- `/compact` reduces model context without deleting the conversation. `/fork`
  starts a separate chat from a safe completed turn so you can explore another approach.
- Drafts, attachments and temporary chats survive switching within the running
  client. An accepted request is not resent after a provider failure.
- The status line helps track context. Remote `/limits` shows the service's
  subscription budget; Local does not inherit server limits.

## Inspect changes and undo them

- `/diff` shows agent changes by file in a scrollable view. `/undo` restores the
  file when later manual changes have not made that unsafe.
- Checkpoints are local and outside the project. Git is not required. Shell
  commands, publications and other external effects cannot be undone this way.
- Writes check for changes since review and preserve permissions and line endings.
  Later manual edits block undo instead of being overwritten.

## Bring your own tools and instructions

- MCP connects personal stdio/HTTP tools on your computer. Each call requires
  confirmation; connection credentials stay local.
- Connections are enabled explicitly. Finding a project configuration does not
  execute it. `/mcp help` explains setup, with GitHub and Playwright examples.
- Skills provide selected instructions and resources for a task. Resource reads
  are explicit, scripts need review and confirmation, and `/skill help` shows examples.

## Work with Python, tests, Git and PRs

- Python symbol maps help locate functions and classes. An optional Python LSP
  adds definitions, references, diagnostics and reviewed rename.
- Unittest execution returns a separate runner report. Affected-test suggestions
  explain their static dependency basis and uncertainty.
- Git tools inspect selected diffs, history and blame. Commits use an explicit
  reviewed file selection without staging unrelated changes.
- Personal GitHub MCP can create/update a draft PR and read checks. It does not
  push or merge automatically. See `/dev help` for the workflow.

## Attach only the document text you need

- PDF: selected pages and source numbers. Scans without text and encrypted files
  are unsupported; the parser does not promise OCR.
- DOCX: paragraphs, sections and tables. CSV: cell ranges with encoding/delimiter
  selection. XLSX: sheets, cells, formula text and saved cached values.
- Attach with `@path#selection`, or ask for the `read_document` tool. `/doc help`
  has examples for all four formats.
- Original binary bytes stay local. Selected text enters context, with explicit
  truncation/partial notices. No formulas, macros or external links are executed.
  Extraction does not reproduce the original page layout.

## Privacy and upgrading

Local contacts providers directly, stores history in local SQLite and requires no
server subscription. Remote uses your server account and subscription budget.
File/document reads, MCP and Git diff tool content are redacted before permanent
storage. Text you explicitly attach to a user message is part of that message.

Linux x64 and Windows x64 downloads include client dependencies. Get your platform's
file and `SHA256SUMS` from the [release](https://github.com/KoTeKaaa/Gemini_CLI/releases/tag/v3.0.0),
verify the checksum and check the version with `gemini-cli --version`.

Remote operators should check the [history schema](https://github.com/KoTeKaaa/Gemini_CLI/blob/v3.0.0/docs/history-migration.md)
and [deployment bundle](https://github.com/KoTeKaaa/Gemini_CLI/blob/v3.0.0/docs/auto-deploy.md)
before updating; those tagged guides are in Russian. Deployment preserves the
environment but does not run SQL migrations automatically.
