# Gemini CLI 3.0.0 — работа с проектом в одном диалоге

В 3.0.0 стало проще довести разговор до результата: найти нужный код, обсудить
изменение, посмотреть diff, запустить проверку и подготовить коммит. Длинные чаты
можно продолжать и разветвлять, а документы — читать по нужным страницам и ячейкам.
Вы по-прежнему решаете, какие файлы читать и какие действия выполнять.

## Чаты, к которым удобно возвращаться

- Постоянная история получила устойчивые границы ходов. Продолжение после отмены
  или ошибки сохраняет порядок сообщений и результатов инструментов.
- `/compact` сокращает контекст длинного разговора, сохраняя саму переписку.
  `/fork` создаёт отдельный чат с допустимым префиксом: можно попробовать другой
  подход и вернуться к исходной беседе.
- Черновики, вложения и временные чаты сохраняются при переключении внутри
  запущенного клиента. Принятый запрос не отправляется повторно после ошибки провайдера.
- Строка состояния помогает следить за контекстом. В Remote `/limits` показывает
  бюджет серверной подписки; в Local серверные ограничения не навязываются.

## Правки, которые можно посмотреть и отменить

- `/diff` показывает изменения агента по файлам в отдельном прокручиваемом окне.
  `/undo` возвращает файл к состоянию до этих правок, если после них вы его не меняли.
- Контрольные точки хранятся локально вне проекта. Откат работает и без Git;
  команды оболочки, публикации и другие внешние действия в него не входят.
- Запись проверяет, не изменился ли файл после просмотра, сохраняет права и
  переводы строк. Поздние ручные изменения блокируют откат, чтобы не затереть вашу работу.

## Свои инструменты и инструкции

- MCP подключает персональные инструменты по stdio или HTTP. Клиент показывает
  доступные возможности и запрашивает подтверждение вызова; ключи остаются на вашей машине.
- Подключение включается явно. Найденные в проекте конфиги не запускаются сами.
  Начать можно с `/mcp help`; отдельно описаны GitHub и Playwright MCP.
- Skills позволяют выбрать набор инструкций и материалов для конкретной задачи.
  Ресурсы читаются по запросу, а скрипты запускаются только после подтверждения.
  `/skill help` объясняет формат и настройку на простых примерах.

## Код, проверки, Git и PR

- Карта Python-символов помогает найти функции и классы. Опциональный Python LSP
  добавляет переход к определениям, поиск ссылок, диагностику и переименование
  с предварительным просмотром изменений.
- Запуск unittest возвращает отдельный итог проверки. Подсказки затронутых тестов
  объясняют, на каких зависимостях основан выбор и где он может быть неполным.
- Инструменты Git читают выбранные diff, историю и blame. Коммит готовится по
  явно выбранным файлам и подтверждённому плану, без добавления посторонних правок.
- Персональный GitHub MCP помогает создать или обновить PR и прочитать его проверки.
  Push и merge автоматически не выполняются. Примеры доступны в `/dev help`.

## Нужный фрагмент документа вместо всего файла

- PDF: выбранные страницы с номерами источника; сканы без текста и зашифрованные
  документы обозначаются как неподдерживаемые, без обещания OCR.
- DOCX: абзацы, разделы и таблицы. CSV: диапазоны с явной кодировкой и разделителем.
  XLSX: список листов и выбранные ячейки с формулами и сохранёнными значениями.
- Прикрепление работает через `@путь#выбор`, чтение агентом — через `read_document`.
  `/doc help` содержит готовые примеры для всех четырёх форматов.
- Исходные бинарные файлы не отправляются. В контекст попадает выбранный текст;
  усечение и неполное извлечение обозначаются явно. Формулы, макросы и внешние
  ссылки не исполняются. Это извлечение текста, а не воспроизведение оформления.

## Приватность и обновление

Local обращается к провайдеру напрямую, хранит историю в локальной SQLite и
не требует серверной подписки. Remote использует аккаунт и бюджет вашего сервера.
Результаты чтения файлов, документов, MCP и Git diff очищаются перед сохранением
постоянной истории. Текст, который вы сами прикрепили к сообщению, остаётся частью
этого сообщения; не прикрепляйте секреты, которые не хотите отправлять модели.

Готовые сборки для Linux x64 и Windows x64 содержат зависимости клиента.
Скачайте нужный файл и проверьте его по `SHA256SUMS`, как описано в
[руководстве по установке](../../README.md#-готовый-релиз-для-linux-и-windows).
Проверить версию можно командой `gemini-cli --version`.

Владельцам Remote-сервера перед обновлением стоит сверить
[схему истории](../history-migration.md) и обновить
[программу автодеплоя](../auto-deploy.md). Автодеплой сохраняет рабочее окружение
с ключами, но не выполняет SQL-миграции автоматически.
