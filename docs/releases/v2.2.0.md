# 🚀 Gemini CLI 2.2 — длинные диалоги и удобное восстановление

Работать с проектом из терминала стало спокойнее: переписка сохраняется целиком,
черновики ждут в своих чатах, а от удачного ответа можно начать отдельный диалог!

## 🧠 Больше места для разговора

- `/compact` собирает старые завершённые ходы в сводку, сохраняя исходную переписку и последние ходы целиком.
- Автоматическое сжатие учитывает полученный от провайдера предел модели и резерв ответа; неизвестные значения не подменяются нулём.
- CLI различает оценку контекста и измеренные значения, учитывает инструкции, инструменты и вложения.
- Ошибка или отмена генерации сводки сохраняет прежний контекст; неудачная попытка не повторяется по кругу.

## 📂 Каждый чат помнит своё

- История, текст, файлы, изображения и большие вставки черновика сохраняются в памяти при переключении чатов и Local/Remote.
- Поиск по названию, недавние чаты и отметка текущего диалога ускоряют навигацию.
- `/clear` очищает только временный чат и его черновик; постоянные диалоги сохраняются.
- `/fork Название` создаёт отдельный постоянный чат до выбранного завершённого хода, сохраняя исходник.
- Текст неудачного или отменённого запроса можно вернуть в черновик форка после подтверждения. Отправка остаётся ручной, инструменты повторно не запускаются; вложения нужно прикрепить заново.

## ✨ Ответ в центре внимания

- Потоковый ответ открывается на временном экране со статусом «Gemini думает»; готовый Markdown выводится в основной терминал один раз.
- `Esc` отменяет ход и отсекает поздние события, а `F2` раскрывает вывод инструментов только по вашему запросу.
- `/term` по-прежнему открывает настоящую ручную оболочку и возвращает в тот же чат после выхода.

## 🔒 Личные ключи или серверный аккаунт

- Local работает напрямую с Gemini, хранит постоянные чаты в приватной SQLite и не требует сервера или Supabase.
- Remote использует приглашённый аккаунт и подписку; панель владельца управляет доступом и бюджетом.
- История Local/Remote изолирована, а ключи Local остаются в системном хранилище либо явно только в памяти.
- Постоянная история хранит идентификаторы и статусы ходов; повторная доставка событий не дублирует записи.

## 📦 Готовые сборки

- `gemini-cli-linux-x64` — Linux x64, сборка на Ubuntu 22.04; включает Local и Remote.
- `gemini-cli-windows-x64.exe` — Windows x64; включает Local и Remote.
- `SHA256SUMS` — контрольные суммы обоих файлов.

На Linux скачайте бинарный файл и `SHA256SUMS`, выполните
`sha256sum --ignore-missing -c SHA256SUMS`, затем `chmod +x gemini-cli-linux-x64` и
`./gemini-cli-linux-x64`. На Windows сравните результат
`Get-FileHash .\gemini-cli-windows-x64.exe -Algorithm SHA256` с записью в `SHA256SUMS`,
затем запустите `.\gemini-cli-windows-x64.exe` в PowerShell.

Обе сборки публикуются только после успешной проверки автономного запуска
с временным профилем. Устанавливать Python отдельно не нужно: выберите Local
с личным Gemini API key или Remote с адресом своего сервера при первом запуске.

Для обновления собственной серверной установки сверяйтесь с
[руководством миграции истории](https://github.com/KoTeKaaa/Gemini_CLI/blob/v2.2.0/docs/history-migration.md):
SQL применяется отдельно от автодеплоя. Локальная SQLite обновляется при открытии.
