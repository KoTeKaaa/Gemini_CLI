# Переносимые навыки

В CLI откройте `/skill help`: пошаговое руководство для первого навыка,
готовые шаблоны `SKILL.md`/JSON и добавление нескольких навыков.
Справка прокручивается на отдельном экране; Esc возвращает в чат.

Навык — каталог с `SKILL.md`: YAML-метаданные и инструкции в Markdown.
Gemini CLI использует [формат Agent Skills](https://agentskills.io/specification).
Совместимость конкретного навыка с другими агентами зависит от их инструментов
и правил. Поле `allowed-tools` не предоставляет разрешений в Gemini CLI.

## Установка

Скопируйте выбранные каталоги из [примеров](skills-examples) в личную папку,
например `~/my-skills`. Просмотрите инструкции и скрипты перед использованием.
Расположение каталога проекта само по себе не включает его навыки.

Создайте `skills.json` в приватном каталоге CLI:
Linux — `~/.gemini_cli/skills.json`, Windows — `%USERPROFILE%\.gemini_cli\skills.json`.
Укажите абсолютные пути к папкам, содержащим каталоги навыков:

```json
{"version": 1, "directories": ["/home/USER/my-skills"]}
```

Пример значения `directories` для Windows:
`["C:\\Users\\USER\\my-skills"]`. Замените `USER` и пути своими.
`~`, переменные окружения и относительные пути в JSON не раскрываются.
Конфигурация относится к локальному CLI и используется в обоих режимах.
Не помещайте в неё ключи, токены и пароли.

Структура примера:

```text
my-skills/
  code-review/
    SKILL.md
    references/checklist.md
    scripts/checklist.py
  task-plan/
    SKILL.md
    assets/plan.md
```

## Выбор и отключение

- `/skill` — каталог, ошибки обнаружения и активный навык.
- `/skill use code-review` — загрузить инструкции одного выбранного навыка.
- `/skill off` — отключить его и освободить ресурсы и локальный вывод.

Команды, действия и имена дополняются через Tab. В строке состояния появляется
`skill code-review`. Выбор действует для последующих сообщений текущего чата;
явные инструкции пользователя имеют приоритет. Смена чата, аккаунта, режима или
workspace сбрасывает выбор. `/clear` тоже сбрасывает его. После перезапуска CLI
навык нужно выбрать заново. Повторный `use` перечитывает файл и сбрасывает ресурсы.

Список читает только frontmatter, без тела и вложенных файлов. Обнаружение,
просмотр и выбор не вызывают LLM. Служебная оценка контекста учитывает выбранный
навык; в Remote его текст передаётся серверу для оценки и генерации. В Local
генерация идёт напрямую к провайдеру. Текст навыка и ресурсов не записывается
в историю чата как отдельные сообщения. Ответ модели может цитировать их,
поэтому не храните секреты в инструкциях.

Старый сервер без поддержки skills отклоняется до отправки выбранного навыка.
Обновите сервер либо выполните `/skill off`. Существующие проверки подписки
Remote действуют и для запросов с навыком.

## Ресурсы и скрипты

Пути указываются относительно выбранного навыка; файлы с пробелами заключайте
в кавычки. Читать всё содержимое навыка автоматически CLI не будет.

```text
/skill show references/checklist.md
/skill read references/checklist.md
/skill show scripts/checklist.py
/skill run scripts/checklist.py
/skill output
```

`show` открывает локальный просмотр с выходом по Esc и ничего не добавляет
к запросу. `read` добавляет только указанный текстовый ресурс к выбранным
инструкциям для следующих сообщений. Суммарный контекст навыка — до 64 КиБ.

`run` доступен только для просмотренного файла внутри `scripts/`, с отдельным
подтверждением. Изменение файла после просмотра блокирует запуск: откройте его
заново. Выполняется приватный снимок просмотренного текста через существующий
процесс CLI, в текущем workspace. Это обычная программа с правами пользователя;
внешние изменения и shell-действия не откатываются через `/undo`.

Поддерживаются `.py`, `.sh`, `.ps1`; нужны соответствующие Python, Bash или `pwsh`.
При запуске CLI из исходников Python-скрипты используют его интерпретатор.
Для собранного CLI Python устанавливается отдельно и должен быть в `PATH`.
Параметры скрипту не передаются. Скрипт должен быть самостоятельным:
его `__file__` указывает на временный снимок, соседние файлы и относительные
импорты из исходного каталога туда не копируются. Рабочая папка — workspace.
Неизвестные языки не запускаются, зависимости автоматически не устанавливаются.

Esc останавливает процесс, F2 показывает ограниченный вывод во время выполнения.
После завершения `/skill output` открывает последний вывод локально, включая
ошибки. Вывод скрипта не отправляется модели автоматически. Время выполнения
ограничено 120 секундами, вывод — существующим ограниченным буфером процесса.

## Ограничения и удаление

До 16 каталогов, до 256 записей в каждом; файл — до 64 КиБ, YAML frontmatter —
до 8 КиБ. Нужен текст UTF-8. Обязательны `name` и `description`; имя каталога
должно совпадать с `name` (до 64 символов, строчные латинские буквы, цифры и
одиночные дефисы). Описание — до 1024 символов. Поддерживаются многострочные
описания, `license`, `compatibility`, строковый `metadata`, `allowed-tools`.
YAML tags, aliases, anchors и повторные поля верхнего уровня отклоняются.
Навыки с одинаковыми именами недоступны до устранения дубликата.

Ссылки, junction, выход за каталог и известные секретные файлы запрещены.
Установленные навыки не получают доступа к ключам MCP или backend через CLI.
Инструкции и ресурсы не обходят подтверждения обычных инструментов.

Для удаления сначала `/skill off`, затем удалите каталог навыка либо его
родительскую папку из `directories`. Следующий просмотр списка перечитает
конфигурацию. Уже выбранный навык — снимок; удаление файла само по себе его
не отключает, поэтому используйте `off`.
