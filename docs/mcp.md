# MCP: подключения и наборы инструментов

MCP выполняется на компьютере пользователя в обоих режимах. Remote передаёт
серверу ограниченные объявления и выбранные результаты, без конфигурации,
команд запуска, env и bearer-токенов. Для Remote сервер должен объявлять
`mcp-tools-v1`, а подписка — разрешать возможность `mcp`. Старый сервер получает
понятный отказ; Local не требует серверной подписки.

Полная сборка включает MCP SDK 2.3.0 (MIT, Python 3.10+). При облегчённой установке
из исходников добавьте `python -m pip install -r client/requirements-mcp.txt`.
SDK имеет собственные транспортные зависимости; запуск сервера приложения для
MCP не нужен. Для защищённого хранения добавьте keyring из local-зависимостей.

## Конфигурация

Создайте `mcp.json` в приватном каталоге CLI: `$HOME/.gemini_cli` на Linux или
`$env:USERPROFILE\.gemini_cli` на Windows. Конфигурации из workspace не читаются.
Не помещайте токены, пароли, секретные env или аргументы в этот файл.
Пример подключения к официальному GitHub MCP:

```json
{"version": 1, "servers": [
  {"name": "github", "transport": "http",
   "url": "https://api.githubcopilot.com/mcp/x/repos/readonly",
   "auth": "bearer", "tools": ["get_file_contents"], "timeout": 30}
]}
```

Поддерживаются `stdio` (`command`, `args`, `env_keys`) и Streamable HTTP
(`url`, `auth`: `none`, `bearer`, `oauth`). `env_keys` перечисляет только имена;
значения вводятся через `/mcp login`. URL требует HTTPS без credentials/query/
fragment. Частный адрес или локальный HTTP разрешается только отдельным
`allow_private: true` в доверенной записи. Redirect не принимается; задайте
конечный URL. TLS проверяется, публичные IP закрепляются на время соединения.

После изменения файла перезапустите CLI. Чтение файла ничего не запускает.
Каждое подключение/включение выполняется явно; выбор наборов действует до
завершения процесса, отдельно для backend/account. Не более 8 подключений,
16 объявленных MCP tools суммарно, 32 КиБ схем. `tools` позволяет оставить
небольшой список исходных имён. Без списка каталог предлагает поддерживаемые
инструменты в пределах лимита; остальные видны с причиной отказа.

```text
/mcp
/mcp check github
/mcp tools github
/mcp enable github
/mcp disable github
/mcp login github memory
/mcp login github keyring
/mcp logout github
```

`check` запускает доверенный процесс/соединение и обновляет каталог, но не
включает набор для модели. `enable` подключает при необходимости и включает
кэшированный каталог. `disable` завершает подключение и исключает набор из
следующего запроса. `login` подключает для проверки, но не включает автоматически.
Каждый вызов MCP отдельно показывает аргументы и требует `y/n`; даже annotation
read-only не заменяет подтверждение. `/undo` не отменяет внешние действия.

После `/mcp ` предлагаются действия, после действия — имена подключений,
после `/mcp login имя ` — `memory`/`keyring`. Ввод bearer/env скрывается звёздочками,
не сохраняется в истории ввода и не переносится в строку чата.

`memory` хранит credentials до выхода. `keyring` требует работающего хранилища ОС;
при ошибке нет автоматического plaintext/memory fallback. Способ хранения
запоминается отдельно для профиля/подключения. `logout` удаляет локальные tokens,
registration и настроенные env; доступ на стороне сервиса отзывается отдельно.
OAuth использует SDK, PKCE/state и loopback callback; требуется сервис с
поддерживаемой регистрацией OAuth клиента. Отмена/таймаут не дают скрытого входа.
Если сервис требует заранее зарегистрированный client_id, используйте его
документированный bearer-доступ; произвольная регистрация не выполняется вручную.

Каталог отвергает refs/composition/union и неподдерживаемые ограничения схемы;
служебные `title`, `default`, `$schema` известного dialect и `x-mcp-header`
нормализуются без исполнения. Имена модели устойчивы: `mcp_<сервис>_<hash>`.
Входная stdio-строка ограничена 256 КиБ до JSON-разбора; HTTP-ответ — 256 КиБ,
сжатые ответы не принимаются. Результат для модели ограничен 8 КиБ;
текст embedded resources читается, бинарные media
пропускаются с отметкой. Приватные аргументы/результаты MCP не сохраняются
в постоянной истории, fork и контексте сжатия. MCP/HTTP diagnostics не записывают
сырые ответы и токены. Esc прекращает новые вызовы и отменяет ожидание;
уже выполненное внешнее действие может сохраниться.

Настройка сервисов: [GitHub](mcp-github.md), [Playwright](mcp-playwright.md).
