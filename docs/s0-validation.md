# Проверка S0

Проверено 19 октября 2026 года. Это статус проверки реализации, а не объявление
о завершённой production-миграции или полной приёмке спринта.

- Полная регрессия после исправлений независимого ревью: 177 тестов, OK;
  один тест реального Supabase пропущен из-за отсутствия тестовых credentials.
- Deployment preflight: PASS. Проверки выборочной runtime-поставки и импортов
  подтверждают отсутствие server SDK в remote и server/UI зависимостей в local.
- Linux: сборка обоих режимов и автономный запуск на чистом временном профиле — PASS.
  Состав архива: Gemini, SQLite, оба backend и Secret Service; FastAPI/Supabase отсутствуют.
- Linux Secret Service: синтетический ключ записан, прочитан новым экземпляром
  напрямую из ОС и удалён без обращения к личным ключам.
- Изолированный PostgreSQL preview: четыре миграции, SQL-сценарии RLS двух
  пользователей, version conflicts, бюджет и активация — PASS. Для auth.uid
  используется test fixture; это не проверка входа в настоящий Supabase Auth.
- Параллельные RPC в PostgreSQL: при одном бюджетном слоте один запрос получает
  reserved, второй exhausted; при одной ссылке только один из двух аккаунтов активируется.
  После перезапуска preview-БД повтор зарезервированного request_id возвращает duplicate.
- Независимое ревью: исправлены блокировка чата без tools, размер результатов,
  восстановление старых больших сообщений и согласованность пределов batch/истории.
  Повторное ревью не выявило оставшихся блокирующих дефектов в просмотренном коде.
- Rich alternate screen, однократный итоговый Markdown, порядок calls/IDs/signatures
  и сохранность истории при смене режима покрыты регрессией.

## Что остаётся открытым

- Windows: обязательная сборка и автономный запуск текущей ветки в CI.
- Отдельный Supabase preview с отключёнными signup/anonymous, владельцем панели,
  реальными сессиями двух аккаунтов и проверкой RLS через пользовательские токены.
- TLS двух origins, внешний отказ доступа к backend и ручной браузерный сценарий:
  вход владельца/отказ обычному пользователю, приглашение, активация, отзыв и смена сети.
- Контролируемый запрос в Local с введённым пользователем личным Gemini-ключом
  через мастер на чистом профиле; реальная проверка credential storage на Windows.

Действующий VPS-сервис и настройки рабочего Supabase не изменялись. Отдельные
preview PostgreSQL и синтетические fixtures не выдают себя за полную приёмку.
Спринт и перевод изменений в production остаются открытыми до этих проверок.
