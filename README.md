# Gemini_CLI

`Gemini_CLI` — это продвинутый интерактивный консольный клиент для работы с Gemini через локальный или удалённый FastAPI-сервер.

Проект поддерживает авторизацию через Supabase, выбор и управление чатами, потоковую выдачу ответов ИИ с красивым рендерингом Markdown, а также **интеграцию с локальной системой (Tool Use / Agentic capabilities)** в безопасном режиме.

---

## ⚡ Ключевые возможности

### 🤖 Интеграция с локальной системой (Tool Use)
ИИ может взаимодействовать с вашим компьютером прямо во время диалога. В одном ответе модель может вызвать несколько инструментов, при этом контекст диалога сохраняется.
- **Чтение файлов (`read_local_files`):** ИИ может запросить содержимое одного или нескольких файлов проекта. Известные файлы с секретами клиент не читает.
- **Запись и модификация файлов (`write_local_files`):** ИИ может изменять код или создавать новые файлы с обязательным предпросмотром и подтверждением пользователя. Запись идёт через временный файл с заменой после успешной записи; результат показывается для каждого файла.
- **Выполнение команд терминала (`execute_command`):** ИИ может компилировать, запускать тесты или устанавливать библиотеки. Команда выполняется только после вашего явного одобрения (y/n) и защищена таймаутом в 120 секунд.
- **Песочница (Sandbox):** доступ ограничен текущей рабочей папкой. Переход наружу через `..` или символическую ссылку блокируется.

### 💻 Удобный CLI-интерфейс (Rich & Prompt-Toolkit)
- **Потоковый Markdown:** ответы плавно выводятся на экран с подсветкой синтаксиса и форматированием.
- **Интерактивные меню:** выбор чатов и моделей стрелочками на клавиатуре.
- **ASCII-баннер и статус-бары:** отображение текущей модели, режима работы и активной рабочей папки.

### 🔒 Безопасность и управление сессией
- **Авторизация:** вход по email и паролю через Supabase Auth (с быстрой регистрацией прямо из CLI).
- **Сохранение сессии:** токены и конфиг сервера кэшируются в `~/.gemini_cli/`. На POSIX-системах каталог и файл сессии доступны только владельцу.
- **Автообновление сессии:** истёкшая сессия обновляется по refresh token; если не получилось, клиент предлагает войти заново.
- **HTTPS:** для удалённого сервера обязателен HTTPS, HTTP разрешён только для `localhost` и loopback-адресов. Чаты разных пользователей изолированы.
- **Защита выполнения:** ни одно изменение файлов и ни один запуск команд не происходит автоматически — клиент всегда запрашивает подтверждение.

### 📂 Управление чатами
- **Постоянные чаты:** история хранится в Supabase (таблицы `chats` и `messages`).
- **Временные чаты:** быстрые сессии без сохранения истории в БД.
- **Удаление:** удаление комнат прямо из интерфейса. При отмене меню `/chat` текущий чат сохраняется.

## 🛠 Команды внутри CLI

| Команда | Описание |
| :--- | :--- |
| `/help` | Показать интерактивную справку |
| `/model` | Быстро переключить активную модель ИИ |
| `/chat` | Сменить комнату диалога или создать новую |
| `/delete` | Удалить текущий постоянный чат из базы данных |
| `/cd {путь}` | Изменить рабочую директорию проекта для ИИ (в том числе по относительному пути) |
| `exit`, `quit`, `q` | Безопасный выход из приложения |

## 🧱 Структура проекта

- `main.py` — интерактивный CLI-клиент с поддержкой вызова локальных инструментов
- `server.py` — FastAPI-сервер: авторизация, чаты и запросы к Gemini API и Supabase
- `client/` — зависимости, запуск и сборка клиента на Linux
- `deploy/` — установщик и конфигурация сервера для Ubuntu/Debian
- `tests/` — тесты клиента, сервера и предварительных проверок установщика

## 🚀 Настройка и запуск

### 1. Запустить сервер

#### Локально

Рекомендуется виртуальное окружение:

```bash
# Создание окружения
python -m venv .venv

# Активация (Windows)
.\.venv\Scripts\Activate.ps1

# Активация (Linux/macOS)
source .venv/bin/activate

# Установка зависимостей
pip install -r requirements.txt
```

Создайте файл `.env` в корневой папке проекта:

```env
API_KEY=your_gemini_api_key
SUPABASE_URL=your_supabase_url
SUPABASE_ANON_KEY=your_supabase_anon_key
```

Запустите сервер:

```bash
python server.py
```

Этот способ слушает `0.0.0.0:8000` без TLS. Для VPS используйте скрипт ниже.

#### Автоматическая установка на VPS (Ubuntu/Debian)

Создайте **вне репозитория** файл с `API_KEY`, `SUPABASE_URL` и `SUPABASE_ANON_KEY` в формате `KEY=value`. На сервере из каталога проекта запустите:

```bash
sudo ./deploy/install.sh --host SERVER_IP --env-file /absolute/path/server.env
```

Скрипт спросит, существует ли сертификат. При ответе «да» передайте пути к имеющимся файлам (или сразу укажите их в команде):

```bash
sudo ./deploy/install.sh --host SERVER_IP --cert-mode existing \
  --cert-file /absolute/path/fullchain.pem --key-file /absolute/path/privkey.pem \
  --env-file /absolute/path/server.env
```

При ответе «нет» скрипт выпустит бесплатный сертификат Let's Encrypt для публичного IP или DNS-имени через acme.sh и настроит его продление. Для выпуска и продления **публичный TCP-порт 80 должен быть открыт и свободен**. Порт 443 не требуется. Для запуска без вопросов используйте `--cert-mode issue`. Не используйте этот режим, если порт 80 занят другим сервисом; укажите существующий сертификат. Перед установкой можно проверить существующий сертификат командой `sudo ./deploy/install.sh --check` с теми же параметрами. acme.sh устанавливается отдельно для этого сервиса и не меняет сертификаты 3x-ui.

Порт HTTPS по умолчанию — `9443`; другой задаётся через `--port`. Скрипт проверяет совпадение сертификата с адресом, при отсутствии Python устанавливает его, создаёт `/opt/gemini-cli/.venv` и устанавливает серверные зависимости. Затем он копирует **только три** необходимые переменные в `/etc/gemini-cli/server.env` с правами `0600`, запускает API на `127.0.0.1:8000`, Nginx на выбранном HTTPS-порту и включает автозапуск. Таймер перечитывает обновлённый сертификат каждый час. Для существующего сертификата его продление должно быть настроено отдельно; для выпущенного скриптом это делает acme.sh через cron.

После установки проверьте доступность HTTPS-порта с другого устройства и откройте его в сетевых правилах хостинга, если требуется.

### 2. Запустить CLI-клиент

На Linux из каталога проекта:

```bash
./client/run.sh
```

При первом запуске скрипт проверяет Python 3.10+, создаёт `.venv`, устанавливает только клиентские зависимости и запускает `main.py`. Для одной только установки окружения используйте `./client/run.sh --setup-only`. Если Python установлен под другим именем, задайте `PYTHON=/путь/к/python3`.

На Windows установите клиентские зависимости и запустите клиент:

```powershell
python -m pip install -r client/requirements.txt
python main.py
```

При первом запуске клиент попросит ввести адрес сервера и запомнит его. Для сервера, установленного скриптом, это:

```text
https://SERVER_IP:9443
```

Сертификат должен соответствовать указанному IP или DNS-имени. Прямое подключение по HTTPS к `server.py:8000` не работает; для удалённого сервера нужен HTTPS. Если адрес введён без протокола, приложение выбирает HTTPS для удалённого адреса и HTTP для локального.

## 🤖 Поддерживаемые модели

По умолчанию используется `gemini-3.5-flash-lite`. Через `/model` можно выбрать:

| Модель | Идентификатор API |
| --- | --- |
| Gemini 3.5 Flash-Lite | `gemini-3.5-flash-lite` |
| Gemini 3.8 Flash | `gemini-3.8-flash` |
| Gemini 3.7 Flash | `gemini-3.7-flash` |
| Gemini 3.6 Flash | `gemini-3.6-flash` |
| Gemini 3.5 Flash | `gemini-3.5-flash` |

Это стабильные модели для текстового ответа и вызова функций из [списка Gemini API](https://ai.google.dev/gemini-api/docs/models). Доступность и лимиты зависят от ключа API и отображаются в Google AI Studio. Клиент передаёт выбранный идентификатор серверу, а сервер вызывает `client.models.generate_content_stream` из Google Gen AI SDK. Для продолжения после вызова инструмента Gemini 3 клиент возвращает выданную моделью `thought_signature` вместе с вызовом.

## 📦 Готовый файл и сборка

Для Linux выполните из каталога проекта:

```bash
./client/build.sh
./dist/gemini-cli
```

Скрипт устанавливает PyInstaller и создаёт один исполняемый файл `dist/gemini-cli`. В нём уже находятся Python и клиентские зависимости; `server.py` и серверные ключи туда не входят. Файл собран для архитектуры и системных библиотек компьютера сборки; для другой Linux-системы соберите его там же или на совместимой системе. Адрес сервера и сессия хранятся в домашней папке пользователя, как при запуске через Python. Для GitHub Release приложите `dist/gemini-cli` как файл релиза и укажите целевую архитектуру и дистрибутив сборки. Каталоги `dist/`, `build/` и `.venv/` не добавляются в Git.

Для Windows `.exe` собирается на Windows через PowerShell:

```powershell
./client/build.ps1
```

Скрипт создаёт отдельное окружение `.venv-win`, устанавливает клиентские зависимости и PyInstaller. После сборки файл находится в `dist\gemini-cli.exe`. Если Windows-компьютера нет, после push в ветку `dev` workflow `Build Windows client` соберёт `.exe` на GitHub Actions. Скачайте артефакт `gemini-cli-windows-x64` из завершённого запуска и приложите `.exe` к GitHub Release. Сборка на Windows должна завершиться успешно до публикации файла.

## 📝 Логирование

Все системные события, ошибки подключения и вызовы инструментов логируются в локальный файл:
`~/.gemini_cli/gemini_cli.log`

Лог вызовов инструментов не содержит их аргументы.

## 📌 Примечания

- Для постоянных чатов сервер использует таблицы Supabase `chats` и `messages`.
- Для удаления чата вместе с сообщениями в БД необходим внешний ключ `messages.chat_id` с `ON DELETE CASCADE`. Сервер проверяет владельца чата перед чтением истории и удалением; RLS в Supabase также должна быть настроена.
- Результаты чтения локальных файлов не сохраняются в истории постоянного чата в открытом виде.
- При ошибке `429` сервер сообщает, что у модели закончились бесплатные токены или лимит запросов, и предлагает сменить модель.
