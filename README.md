# Gemini_CLI

`Gemini_CLI` — интерактивный консольный клиент Gemini с двумя режимами: самостоятельный **Local** с личными ключами и **Remote** через сервер с подпиской аккаунта.

Проект поддерживает авторизацию через Supabase, выбор и управление чатами, потоковую выдачу ответов ИИ с красивым рендерингом Markdown, а также **интеграцию с локальной системой (Tool Use / Agentic capabilities)** в безопасном режиме.

---

## ⚡ Ключевые возможности

### 🤖 Интеграция с локальной системой (Tool Use)
ИИ может взаимодействовать с вашим компьютером прямо во время диалога. В одном ответе модель может вызвать несколько инструментов, при этом контекст диалога сохраняется.
- **Чтение файлов (`read_local_files`):** ИИ может запросить содержимое одного или нескольких файлов проекта. Известные файлы с секретами клиент не читает.
- **Запись и модификация файлов (`write_local_files`):** ИИ может изменять код или создавать новые файлы с обязательным предпросмотром и подтверждением пользователя. Запись идёт через временный файл с заменой после успешной записи; результат показывается для каждого файла.
- **Выполнение команд терминала (`execute_command`):** ИИ может компилировать, запускать тесты или устанавливать библиотеки. Команда выполняется только после вашего явного одобрения (y/n) и защищена таймаутом в 120 секунд. Запускается в текущей рабочей папке, но **не ограничена ею**: процесс имеет те же права, что и ваш пользователь, поэтому читайте команду перед подтверждением.
- **Ограничение рабочей папкой (для файловых инструментов):** чтение и запись файлов ограничены текущей рабочей папкой. Переход наружу через `..` или символическую ссылку блокируется. Это ограничение не распространяется на `execute_command`.

### 💻 Удобный CLI-интерфейс (Rich & Prompt-Toolkit)
- **Потоковый Markdown:** ответы плавно выводятся на экран с подсветкой синтаксиса и форматированием.
- **Интерактивные меню:** выбор чатов и моделей стрелочками на клавиатуре.
- **ASCII-баннер и статус-бары:** отображение текущей модели, режима работы и активной рабочей папки.

### 🌐 Веб-поиск и чтение документации
- **Поиск (`web_search`):** Tavily Basic находит до 5 источников за запрос, а общий бюджет и кэш помогают экономно использовать бесплатную квоту.
- **Чтение страниц (`read_url`):** сервер загружает публичные HTML/plain-text страницы, выделяет полезный текст и сообщает об усечении. Кредиты Tavily для этого не нужны.
- **Понятные источники:** CLI отдельно показывает найденные и прочитанные страницы, включая конечный URL после перенаправления.
- **Гибкая работа:** без ключа поиска по-прежнему доступны обычный чат, чтение URL и локальные инструменты.

### 🎯 Точная работа с проектом
- **Поиск файлов (`find_files`)** помогает быстро найти нужные пути без чтения содержимого.
- **Поиск текста (`search_text`)** и **диапазоны строк (`read_file_lines`)** возвращают ограниченные фрагменты с номерами строк после вашего подтверждения.
- **Точечная замена (`replace_in_file`)** показывает diff и меняет только один уникальный фрагмент, сохраняя права файла и переводы строк.
- **Надёжное продолжение:** все результаты пакета сохраняют порядок и идентификаторы; при достижении лимита цепочка аккуратно завершается после передачи последних результатов.

### 🔒 Безопасность и управление сессией
- **Remote:** вход по email и паролю через Supabase Auth; новый аккаунт приглашает владелец панели. Подписка проверяется перед серверными вызовами.
- **Local:** личные ключи идут прямо провайдерам и хранятся в Secret Service/Windows Credential Locker либо явно только в памяти до закрытия CLI.
- **Сохранение сессии:** токены и конфиг сервера кэшируются в `~/.gemini_cli/`. На POSIX-системах каталог и файл сессии доступны только владельцу.
- **Автообновление сессии:** истёкшая сессия обновляется по refresh token; если не получилось, клиент предлагает войти заново.
- **HTTPS:** для удалённого сервера обязателен HTTPS, HTTP разрешён только для `localhost` и loopback-адресов. Чаты разных пользователей изолированы.
- **Защита выполнения:** ни одно изменение файлов и ни один запуск команд не происходит автоматически — клиент всегда запрашивает подтверждение. Это единственная защита для команд терминала, поэтому подтверждайте их только после того, как прочитаете.

### 📂 Управление чатами
- **Постоянные чаты:** в Local — приватная SQLite профиля, в Remote — Supabase. Между режимами история автоматически не переносится.
- **Временные чаты:** быстрые сессии без сохранения истории в БД.
- **Удаление:** удаление комнат прямо из интерфейса. При отмене меню `/chat` текущий чат сохраняется.

## 🛠 Команды внутри CLI

| Команда | Описание |
| :--- | :--- |
| `Ctrl+V`, `/paste` | Прикрепить скриншот или текст из буфера без отправки |
| `/attachments` | Вертикальный список всех вложений с общими номерами |
| `/remove 1` | Удалить вложение #1 любого типа; остальные номера сохраняются |
| `@file`, `@file:1-20`, `@file:7` | Весь файл, строки 1–20 включительно или только строка 7 |
| `/show 1`, `/edit 1` | Просмотреть вложение #1 или изменить его текст в черновике |
| `/help` | Показать интерактивную справку |
| `/model` | Быстро переключить активную модель ИИ |
| `/settings` | Выбрать Local/Remote, изменить сервер и личные ключи |
| `/chat` | Сменить комнату диалога или создать новую |
| `/delete` | Удалить текущий постоянный чат из базы данных |
| `/cd {путь}` | Изменить рабочую директорию проекта для ИИ (в том числе по относительному пути) |
| `exit`, `quit`, `q` | Безопасный выход из приложения |

## Ввод и изображения

Скопируйте скриншот, нажмите Ctrl+V в строке ввода, добавьте текст и нажмите Enter.
После добавления видны номер, имя и размер вложения. Внизу — компактный счётчик;
`/attachments` показывает полный список по одному вложению на строку. `/paste` выполняет ту же вставку по команде,
если терминал перехватывает Ctrl+V. Текстовая вставка терминала остаётся доступной;
Ctrl+J добавляет строку. Большой вставленный текст показывается компактным блоком.
`/show 1` открывает текст в отдельном полноэкранном просмотре с прокруткой (Esc — назад),
а скриншот — в системном приложении просмотра изображений. Linux использует `xdg-open`
из `xdg-utils`; в ОС должно быть назначено приложение для PNG/JPEG/WebP.
`/edit 1` открывает копию текста в отдельном окне: GNOME Text Editor, gedit или
VS Code на Linux, Блокнот на Windows. Сохраните и закройте окно; на Windows затем
нажмите Enter в CLI, чтобы принять сохранённый текст. Исходный файл не меняется.
Если подходящего редактора нет, команда сообщит об этом и сохранит черновик. `/remove 1` удаляет файл, изображение или вставку;
номера остальных вложений сохраняются. Если вложение одно, номер можно опустить для `/show` и `/edit`.
`/remove` без номера всегда показывает список и ничего не удаляет.
После `/remove `, `/show ` и `/edit ` доступны подсказки номеров.
Старые `/paste-show`, `/paste-edit`, `/paste-remove`, `/remove-file` остаются совместимыми
именами общих команд с той же нумерацией.

Windows использует системный буфер Win32. На Linux Wayland установите `wl-clipboard`
(команда `wl-paste`), на X11 — `xclip`, например `sudo apt install wl-clipboard xclip`.
Нужен локальный графический сеанс; SSH без доступа к нему не переносит буфер компьютера.
Списки скопированных файлов не открываются автоматически: используйте `@путь`.
Подсказки `@` начинаются в начале строки, поддерживают пробелы и Unicode;
`@file:1-20` прикрепляет строки 1–20 включительно. Двоеточие вводится буквально,
квадратные скобки не нужны; `@file:7` выбирает одну строку. Диапазон виден в списке вложений. После Enter на выбранном пути
напишите сообщение и отправьте его следующим Enter.

Лимиты: статические PNG/JPEG/WebP, 2 МиБ и 12 млн пикселей на изображение,
до 4 изображений, всего до 4 МиБ в отправляемом контексте. Старые изображения
могут лишиться байтов при заполнении контекста; метаданные остаются.
Текстовые файлы — UTF-8, суммарно до 24000 байт; выбор через `@file` добавляет содержимое в черновик без повторного вопроса.
Отправка модели происходит только вместе со следующим подтверждённым сообщением.
История хранит только метаданные изображений. До явной команды `/show` байты живут
в памяти; для системного просмотрщика создаётся приватный временный файл (на Linux —
в tmpfs, если доступен). Он удаляется при удалении вложения, отправке/очистке черновика
или выходе из CLI. Если просмотрщик Windows удерживает файл, при выходе показывается
путь папки для удаления после закрытия просмотрщика. После перезапуска
прикрепите нужные изображения повторно. Текст выбранных файлов входит в сообщение.
Local обращается к Gemini напрямую, remote требует обновлённого сервера с контрактом
изображений; при старом сервере запрос отклоняется до отправки вложения.

## 🧱 Структура проекта

- `main.py` — интерактивный CLI-клиент с поддержкой вызова локальных инструментов
- `server.py` — FastAPI-сервер: авторизация, чаты и запросы к Gemini API и Supabase
- `gemini_cli/client/` — цикл инструментов, веб-бюджет и поддержка терминала
- `gemini_cli/tools/` — общие контракты, локальные операции и серверные веб-инструменты
- `gemini_cli/server/` — веб-маршруты, ограничения запросов и политика постоянной истории
- `client/` — зависимости, запуск и сборка клиента на Linux
- `deploy/` — установщик и конфигурация сервера для Ubuntu/Debian
- `tests/` — тесты клиента, сервера и предварительных проверок установщика

## 🚀 Настройка и запуск

### Самостоятельный Local

Сервер, Supabase и `.env` для этого режима не нужны. На Linux:

```bash
./client/run.sh --with-local
```

На Windows установите `client/requirements-local.txt` и запустите `python main.py`.
Готовые сборки включают оба режима. При первом запуске выберите **Local**, затем
хранилище ключей, скрыто введите Gemini API key и необязательный Tavily key.
Проверка доступа читает сведения провайдера и не запускает пробную генерацию.
При недоступном хранилище ОС можно явно выбрать память до закрытия приложения;
ключи не записываются в JSON или `.env`. Неудачная проверка сохраняет прежние ключи.

`/settings` меняет режим и настройки между запросами. История каждого профиля
сохраняется отдельно; при возвращении восстанавливается текущий чат. Ошибка
Local не переключает запрос на сервер. SQLite имеет ограниченные права доступа,
но не зашифрована. Без Tavily доступны Gemini, локальные инструменты и чтение URL.

### Remote и панель владельца

Выберите **Remote**, укажите HTTPS-сервер и войдите в приглашённый аккаунт.
Для доступа нужна активная подписка. Полученную ссылку откройте в браузере,
войдите в нужный аккаунт и подтвердите активацию; затем используйте обычный вход CLI.
Смена сети не меняет подписку. Бюджет подписки — ограничение сервера, а не квота Gemini.

Владелец входит на отдельный HTTPS-порт панели: `/admin/login` → `/admin/`.
Там доступны модели/tools/срок/бюджет, приглашение аккаунта, одноразовая ссылка,
приостановка и отзыв. Письмо приглашения аккаунта и ссылка подписки — разные действия.
Ссылка показывается один раз; перевыпуск отзывает прежнюю неиспользованную ссылку.
Отзыв блокирует следующие вызовы, включая продолжения; уже начатый запрос может завершиться.

Миграции, bootstrap существующих аккаунтов, закрытая регистрация и настройка
`ADMIN_USER_ID`, `ADMIN_ORIGIN`, `ADMIN_SESSION_SECRET`, серверного service key
описаны в [руководстве поставки](docs/subscription-migration.md).

### 1. Запустить сервер

#### Локально

Рекомендуется виртуальное окружение:

```bash
# Создание окружения
python -m venv .venv

# Активация (Windows)
.\.venv\Scripts\Activate.ps1

# Активация (Linux/macOS)
source .venv/bin/activate

# Установка зависимостей
pip install -r requirements.txt
```

Создайте файл `.env` в корневой папке проекта:

```env
API_KEY=your_gemini_api_key
SUPABASE_URL=your_supabase_url
SUPABASE_ANON_KEY=your_supabase_anon_key
```

Запустите сервер:

```bash
python server.py
```

Этот способ слушает только `127.0.0.1:8000` без TLS. Для VPS используйте скрипт ниже.
Перед запуском сервера примените миграции и выдайте подписки; дополнительные
серверные настройки панели перечислены в руководстве поставки выше.

#### Автоматическая установка на VPS (Ubuntu/Debian)

Создайте **вне репозитория** файл с `API_KEY`, `SUPABASE_URL` и `SUPABASE_ANON_KEY` в формате `KEY=value`. На сервере из каталога проекта запустите:

```bash
sudo ./deploy/install.sh --host SERVER_IP --env-file /absolute/path/server.env
```

Скрипт спросит, существует ли сертификат. При ответе «да» передайте пути к имеющимся файлам (или сразу укажите их в команде):

```bash
sudo ./deploy/install.sh --host SERVER_IP --cert-mode existing \
  --cert-file /absolute/path/fullchain.pem --key-file /absolute/path/privkey.pem \
  --env-file /absolute/path/server.env
```

При ответе «нет» скрипт выпустит бесплатный сертификат Let's Encrypt для публичного IP или DNS-имени через acme.sh и настроит его продление. Для выпуска и продления **публичный TCP-порт 80 должен быть открыт и свободен**. Порт 443 не требуется. Для запуска без вопросов используйте `--cert-mode issue`. Не используйте этот режим, если порт 80 занят другим сервисом; укажите существующий сертификат. Перед установкой можно проверить существующий сертификат командой `sudo ./deploy/install.sh --check` с теми же параметрами. acme.sh устанавливается отдельно для этого сервиса и не меняет другие сертификаты.

Порт API по умолчанию — `9443` (`--port`), панели — `9444` (`--panel-port`).
ADMIN_ORIGIN должен точно совпадать с HTTPS-origin панели. Скрипт проверяет сертификат,
создаёт серверный venv и копирует разрешённые переменные в `/etc/gemini-cli/server.env`
с правами `0600`. API слушает loopback; Nginx разделяет рабочие API и страницы панели.
Таймер перечитывает сертификат каждый час. Для существующего сертификата продление
настраивается отдельно; выпущенный скриптом продлевается через acme.sh.

После установки проверьте доступность HTTPS-порта с другого устройства и откройте его в сетевых правилах хостинга, если требуется.

Runtime-поставка включает `server.py`, необходимые серверу модули `gemini_cli/`
и разрешённые шаблоны/static панели. Клиентские адаптеры, тесты, скрытые каталоги,
`__pycache__`, символические ссылки, `.env` и ключи не копируются. Каталог установленного пакета
`/opt/gemini-cli/gemini_cli` полностью управляется установщиком: при повторной
поставке он заменяется подготовленной версией, поэтому удалённые модули не остаются.
Не храните в нём пользовательские файлы. Соседние файлы, окружение `.venv` и
конфигурация вне пакета при этой замене сохраняются.

### Веб-поиск, страницы и локальные инструменты

Внешний серверный env-файл может дополнительно содержать `TAVILY_API_KEY`.
Он копируется только в защищённый `/etc/gemini-cli/server.env` (`0600`),
клиент его не получает. Используйте бесплатный аккаунт без платёжного метода
и без pay-as-you-go; проверьте это вручную в аккаунте до реального поиска.
Режим фиксирован: `basic`, `auto_parameters=false`, до 5 результатов,
до 3 обращений к поиску на исходное сообщение CLI. Повторы запроса в одном
ходе используют кэш; после ошибки нет автоматического повтора или платного fallback.
Без ключа работают обычный чат и чтение URL. При квоте или сетевой ошибке
поиск отключается для текущего хода, остальные инструменты доступны.

`web_search` возвращает источники; `read_url` читает публичную HTML/plain-text
страницу без расхода Tavily. Клиент отдельно отмечает найденные и прочитанные
источники, фактический конечный URL и усечение. Инструкция модели требует
ссылаться на фактические источники; найденная ссылка сама по себе не означает,
что страница была прочитана или использована в ответе.

| Необязательная настройка | По умолчанию | Верхний предел |
| --- | --- | --- |
| `SEARCH_PER_MINUTE` | 10 на пользователя | 60 |
| `READ_PER_MINUTE` | 30 на пользователя | 120 |
| `WEB_TIMEOUT_SECONDS` | 20 секунд | 30 |
| `WEB_MAX_BYTES` | 2097152 | 2097152 |
| `WEB_MAX_CHARS` | 20000 | 20000 |
| `WEB_MAX_REDIRECTS` | 3 | 3 |

Неверная настройка заменяется значением по умолчанию. Лимиты сервера хранятся
в памяти процесса и сбрасываются при его перезапуске. Байтовый предел действует
на загруженные и распакованные данные; redirects и все DNS-адреса проверяются,
TLS проверяет исходное имя. Закрытые адреса, credentials в URL, бинарные страницы
и превышение ограничений возвращают ошибку без раскрытия содержимого.

`find_files` ищет имена без чтения содержимого. `search_text` и `read_file_lines`
требуют подтверждения чтения и отправки результатов модели. Обход ограничен
10000 записями, выдача — 200 совпадениями; файл — 2 МиБ, диапазон — 500 строк
и 20000 символов. Поиск текста читает не более 8 МиБ за вызов. Секреты, бинарные
файлы, служебные каталоги и внешние ссылки пропускаются. `replace_in_file`
меняет один уникальный непустой фрагмент после отдельного подтверждения diff,
повторно проверяет файл и сохраняет права и переводы строк. Приватные аргументы
и результаты новых файловых инструментов вычищаются из постоянной tool-истории;
веб-текст ограничен выдержкой. Это не фильтрует код в обычных сообщениях чата.

Параметры API: [Tavily Search](https://docs.tavily.com/documentation/api-reference/endpoint/search),
парсер: [Trafilatura](https://trafilatura.readthedocs.io/en/latest/usage-python.html).

### 2. Запустить CLI-клиент

На Linux из каталога проекта:

```bash
./client/run.sh
```

При первом запуске скрипт проверяет Python 3.10+, создаёт `.venv`, устанавливает только клиентские зависимости и запускает `main.py`. Для одной только установки окружения используйте `./client/run.sh --setup-only`. Если Python установлен под другим именем, задайте `PYTHON=/путь/к/python3`.

На Windows установите клиентские зависимости и запустите клиент:

```powershell
python -m pip install -r client/requirements.txt
python main.py
```

При первом запуске выберите Remote; клиент попросит адрес сервера и запомнит его. Для сервера, установленного скриптом, это:

```text
https://SERVER_IP:9443
```

Можно ввести просто IP или DNS-имя: для удалённого сервера клиент сам подставит
HTTPS и порт **9443**. Для локального HTTP-сервера используется **8000**;
явно указанный порт сохраняется. Первичная настройка адреса работает и до подключения сервера.

Сертификат должен соответствовать указанному IP или DNS-имени. Прямое подключение по HTTPS к `server.py:8000` не работает; для удалённого сервера нужен HTTPS. Если адрес введён без протокола, приложение выбирает HTTPS для удалённого адреса и HTTP для локального.

## 📦 Готовый файл и сборка

Для Linux выполните из каталога проекта:

```bash
./client/build.sh
./dist/gemini-cli
```

Скрипт устанавливает PyInstaller и создаёт один исполняемый файл `dist/gemini-cli`. В нём уже находятся Python и клиентские зависимости; `server.py` и серверные ключи туда не входят. Файл собран для архитектуры и системных библиотек компьютера сборки; для другой Linux-системы соберите его там же или на совместимой системе. Адрес сервера и сессия хранятся в домашней папке пользователя, как при запуске через Python. Для GitHub Release приложите `dist/gemini-cli` как файл релиза и укажите целевую архитектуру и дистрибутив сборки. Каталоги `dist/`, `build/` и `.venv/` не добавляются в Git.

Для Windows `.exe` собирается на Windows через PowerShell:

```powershell
./client/build.ps1
```

Скрипт создаёт отдельное окружение `.venv-win`, устанавливает зависимости обоих режимов
и PyInstaller. Файл находится в `dist\gemini-cli.exe`. Workflow `Build Windows client`
собирает и проверяет `.exe` после push в `dev` и `feature/**`; артефакт называется
`gemini-cli-windows-x64`. Сборка должна завершиться успешно до публикации файла.

### 🚀 Готовый релиз для Linux и Windows

Workflow `Build and publish release` собирает обе платформы при публикации тега `v*`.
Каждая сборка проходит автономный запуск с временным профилем. Только после
обеих успешных проверок в [Releases](https://github.com/KoTeKaaa/Gemini_CLI/releases)
публикуются `gemini-cli-linux-x64`, `gemini-cli-windows-x64.exe` и `SHA256SUMS`.
Linux-версия собирается на Ubuntu 22.04; собственная сборка остаётся доступна командами выше.

## 📌 Примечания

- Для постоянных чатов сервер использует таблицы Supabase `chats` и `messages`.
- Для удаления чата вместе с сообщениями в БД необходим внешний ключ `messages.chat_id` с `ON DELETE CASCADE`. Сервер проверяет владельца чата перед чтением истории и удалением; RLS в Supabase также должна быть настроена.
- Результаты чтения локальных файлов не сохраняются в истории постоянного чата в открытом виде.
- При ошибке `429` сервер сообщает, что у модели закончились бесплатные токены или лимит запросов, и предлагает сменить модель.

## ✅ Проверки

Проверка импорта пакета использует только стандартную библиотеку. Тест запускает
отдельный Python с пустым окружением и флагом `-S` (без `site-packages`):

```bash
python -B -m unittest discover -s tests -p test_package_import.py -v
```

Эта же команда добавлена отдельным заданием `package-import` в workflow
`Build Windows client` на Python 3.12 без установки зависимостей.
CI собирает клиент для Linux и Windows и проверяет автономный запуск
с временным профилем без серверных ключей.

Остальные проверки в настроенном окружении:

```bash
PYTHONDONTWRITEBYTECODE=1 .venv/bin/python -m unittest discover -s tests -p test_runtime_payload.py -v
PYTHONDONTWRITEBYTECODE=1 .venv/bin/python -m unittest discover -s tests -p 'test_*.py' -q
bash tests/test_deploy_install.sh
```

Тест предварительной проверки установщика не заменяет запуск на реальном VPS. Интеграционный тест с настоящим Supabase запускается отдельно при `RUN_SUPABASE_INTEGRATION=1` и заданных учётных данных двух тестовых пользователей.
